# Модель безопасности Code Mode

## Sandbox исполнения

`execute(js_code)` исполняет код в `node:vm` с контекстом, где **нет** `require`, `process`, `fs`, `fetch`, `Buffer`, таймеров хоста. Доступны только:

- `mcp.<server>.<method>(args)` — адаптеры (единственная дверь наружу);
- примитивы: `Promise`, `JSON`, `Math`, `Date`, коллекции, `console` (перехватывается в лог).

`codeGeneration.strings = false` — никакой `eval` внутри песочницы. Таймаут 60с. Результат капится 100КБ.

## Сетевой доступ

HTTP только внутри адаптеров, только на `baseUrl` своего сервера из реестра. Адаптер n8n добавляет ключ из env; ключ никогда не возвращается в результат и не попадает в логи (логируется хэш кода, имена методов, статусы, тайминги — `exec.log`).

## Confirm-гейт

Методы реестра имеют `danger: read | write | delete`. Перед исполнением сервер **статически** сканирует код на вызовы write/delete-методов:

- найдены и `confirm !== true` → `confirmation_required` со списком опасных методов, код НЕ исполняется;
- `confirm: true` ставит агент — и только после явного «да» пользователя в конвейере (правило SOUL.md; самоодобрение запрещено).

## Verify-after-write

Код в ноды n8n пишется только через `setNodeCode` (сервер читает файл — модель не пересобирает JS) и **обязан** проверяться `verifyNodeCode` (серверная сверка sha256 факта с эталоном). Аудит не верит словам модели — только серверным проверкам.

## Секрет-индирекция

1. **Страж на записи:** если payload для create/update/setNodeCode содержит значение любого известного серверу секрета (из `.env`) — отказ с указанием имени переменной. Workflow носит ссылку `={{$env.NAME}}`, значение подставляет n8n в рантайме из process env (`N8N_BLOCK_ENV_ACCESS_IN_NODE=false`).
2. **Санитайзер экспорта:** `exportWorkflowSafe` вырезает персоналии (`shared`) и редактит паттерны ключей (`pza_`, `ghp_`, `github_pat_`, `sk-`, `Bearer …`); возвращает `rawSecretsFound` — если список не пуст, публиковать нельзя.

## Аудит

`exec.log` — каждая попытка execute: время, sha256-префикс кода, найденные методы, статус (`ok` / `confirmation_required` / `error`), ledger вызовов с таймингами. Аргументы и секреты в лог не пишутся.
